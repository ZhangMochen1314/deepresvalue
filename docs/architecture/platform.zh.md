# 平台架构（对外）

> 本节只描述 DeepResValue **对外可观测**的架构与边界：用户能看到什么、数据流向哪里、能力如何被调度。
> 服务端实现细节不在公开范围，本文也不构成对内部设计的披露。

---

## 1. 一页速览：五条设计取舍

| # | 取舍 | 对用户意味着什么 |
|---|------|------------------|
| 1 | **云端零配置优先** —— 计算环境不装在用户机器上 | 打开浏览器即可用；手机、平板、电脑同一套能力 |
| 2 | **一个账号、一套数据** —— 端只是入口，不是数据孤岛 | 换设备不迁移，会话与产物跟着账号走 |
| 3 | **能力按领域打包** —— 科研领域专家把方法与工具组合成包 | 说清任务即可，不必自己拼工具链 |
| 4 | **过程可溯源** —— 推理、代码、执行、产物逐段落账 | 结论能回到"哪一行代码跑出了这张表" |
| 5 | **本机能力是可选增强** —— 只有用户显式选择才在个人电脑上执行 | 默认不碰你的本机环境；需要时再授权 |

## 2. 端到端链路

```
 用户
  │  一句话任务（中文/英文）
  ▼
┌──────────────────────────────────────────────────────┐
│ 端形态层   网页端 ／ 桌面端 ／ 小程序端                 │
│            （同账号、同数据、同一套交互）               │
└──────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────┐
│ 平台服务层  会话编排 · 专家与技能调度 · 积分计量         │
│             文件与产物管理 · 账号与配额                 │
└──────────────────────────────────────────────────────┘
  │                                   │
  ▼                                   ▼
┌───────────────────────────┐   ┌──────────────────────┐
│ 隔离执行环境（默认路径）   │   │ 用户个人电脑（可选）  │
│ 临时分配 · 任务结束即回收  │   │ 用户显式选择后启用    │
│ 四大计算内核 · 排版引擎    │   │ 原生执行本机任务      │
└───────────────────────────┘   └──────────────────────┘
  │                                   │
  └───────────────┬───────────────────┘
                  ▼
        ┌───────────────────────┐
        │ 云端存储（唯一持久化） │
        │ 上传件 · 中间件 · 产物 │
        └───────────────────────┘
```

三条不变的纪律：

1. **执行面是临时的**：隔离执行环境按任务分配、任务结束即回收，不长期驻留。
2. **持久化只有一处**：正式交付物必须回到云端存储，才能被其他端看到。
3. **本机执行不默认发生**：桌面端只有在用户显式选择"在本机执行"时才触碰本机文件与环境。

## 3. 端形态层

| 端 | 形态 | 主要职责 | 与其它端的关系 |
|----|------|----------|----------------|
| 网页端 | 浏览器应用 | 全功能主入口 | 基线 |
| 桌面端 | 基于 Chromium 的原生客户端 | 原生窗口体验 + 可选的**本机执行**能力 | 复用同一套网页实现，附加本机能力 |
| 小程序端 | 轻量入口 | 移动端快捷使用 | 复用网页实现，只保留平台强制差异 |

**一致性原则**：三端是同一个产品，不是三个实现。界面、流程、数据模型同源；差异只来自"这个端能做什么"，而不是"这个端怎么做"。

---

## 4. 能力层

### 4.1 科研领域专家

129 个科研领域专家，每个专家 = **领域方法 + 专业工作流 + 工具组合**。用户提出任务后，平台按领域匹配专家，由专家指导执行过程。

### 4.2 技能与工具

- **系统技能**：由平台自动注入，覆盖通用科研流程（检索、分析、写作、排版、复现）。
- **自定义技能 / 第三方技能**：用户可安装、可组合。
- **工具**：云端任务的可执行动作集合；桌面端另有独立的**本机工具集**。

### 4.3 计算内核

| 内核 | 用途 |
|------|------|
| Python 3 | 数据分析、机器学习、NLP、可视化 |
| R | 统计建模、计量经济、生物信息 |
| MATLAB 兼容（Octave） | 信号处理、控制系统、数值计算 |
| SPICE（ngspice） | 电路仿真、模拟/数字设计验证 |

### 4.4 排版引擎

- **Word**：按机构模板生成报告
- **LaTeX**：论文、公式、参考文献管理

### 4.5 数据连接器（MCP）

通过 MCP 协议接入外部数据源与工具，数量持续扩张。用户按需启用，凭证由用户自行提供。

### 4.6 BYOK（自带模型密钥）

用户可接入自己的模型服务（OpenAI 兼容协议），平台不介入用户与模型服务商之间的计费。

## 5. 执行模型

### 5.1 两条执行路径

| 路径 | 触发条件 | 运行位置 | 适合场景 |
|------|----------|----------|----------|
| **云端隔离执行**（默认） | 默认，无需配置 | 临时分配的隔离执行环境 | 绝大多数分析、计算、排版任务 |
| **本机执行**（可选） | 用户在桌面端显式选择 | 用户个人电脑 | 需要本机文件、本机软件、本机环境变量或内网资源的任务 |

### 5.2 任务生命周期

```
接收任务 → 匹配专家 → 规划步骤 → 逐步执行
        → 每步产出落账（可溯源）→ 产物回传云端 → 环境回收
```

### 5.3 失败与降级

- **超时**：单步执行有超时上限，超时后返回可读的失败原因，而不是无限等待。
- **取消**：用户可随时取消；取消会终止该任务派生的整棵进程树。
- **失败可见**：失败步骤携带原始输出，不做"静默成功"。
- **降级**：某个连接器不可用时，任务带明确提示继续或停止，由用户决定。

## 6. 数据与留存

| 数据 | 存放位置 | 说明 |
|------|----------|------|
| 上传文件 | 云端存储 | 随会话管理，跨端可见 |
| 执行中间产物 | 云端存储 | 任务结束后仍可回溯 |
| 正式交付物 | 云端存储 | 唯一持久化层；导出为下载 |
| 桌面端本机文件 | 用户电脑 | **不是持久化数据**；不回传则在其他端不可见 |
| 账号与会话元数据 | 平台数据库 | 账号级隔离 |

**访问模型**：数据按账号隔离；分享走链接级授权，链接外泄即可访问——因此不要分享含敏感信息的链接。

**留存**：文件与产物按产品策略保留，用户可随时导出或删除。

---

## 7. 计费与配额

- 计量单位是**积分**，按任务消耗（复杂度、执行时长、模型用量）。
- 新用户注册即获免费额度；额度用完后按需充值。
- 邀请码奖励无上限。
- BYOK 模式下，模型侧费用由用户与模型服务商直接结算。

---

## 8. 边界与不变量

明确写下"不做什么"，比写"能做什么"更重要：

1. **不承诺端到端加密**：传输全程加密；但平台需要读取文件内容才能完成分析。
2. **不承诺离线全功能**：平台能力依赖云端服务，断网时不可用。
3. **不公开服务端实现**：本文与公开仓库只描述对外架构，不含服务端代码与内部设计。
4. **本机执行必须显式授权**：不存在"默认静默在用户电脑上执行"的路径。
5. **产物以云端为准**：只存在于用户本机的文件，不视为平台已保存的交付物。
6. **分享是链接级**：拿到链接即可访问，平台不提供"仅本人可访问"的强承诺。
